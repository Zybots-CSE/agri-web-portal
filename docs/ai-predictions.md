# AgriCSE / Zybots AI predictions

Open `/ai-predictions` from the main navigation. The page displays stored model
outputs, newest received first (up to 100 per open/closed view), and refreshes
every 30 seconds.
It does not train or run an AI model. Output text is displayed as supplied by
that model; confidence is model-reported, not independently calibrated.

## Setup

Set `DATABASE_URL` in `.env.local`, then run `npm run db:migrate` and
`npm run dev`. The migration adds a predictions table without changing readings.

## Send a prediction

Send from your model's server or Python process (replace the host when deployed):

```python
import requests

response = requests.post('http://localhost:3030/api/predictions', json={
    'model': 'agricse-v1',
    'title': 'Your prediction title',
    'category': 'Your prediction type',
    'summary': 'Explanation generated by your model',
    'confidence': 0.92,
    'deviceId': 'PRB-001',
    'spot': 'Paddy Block B',
    'crop': 'Paddy',
    'recommendations': ['Your model recommendation'],
}, timeout=30)
response.raise_for_status()
print(response.json())
```

Required: `model` (1–120 characters), `title` (1–160), `category` (1–80),
`summary` (1–5000). Optional: `confidence` (number, 0–1), `deviceId`
(2–40 letters/digits/dot/dash/underscore), `spot` and `crop` (1–80),
`recommendations` (up to 20 strings, each 1–1000), and `predictedAt`
(ISO-8601 with timezone; defaults to receipt time).

Responses: `201` with `{ prediction }`; `400` for malformed JSON; `422` with
field issues for invalid data. Each successful POST creates a new result;
repeating a POST creates another result.

`GET /api/predictions` returns `{ count, predictions }`, latest 100 received
results. Add `?deviceId=PRB-001` to filter by probe. Labels are snapshots, not
foreign keys: they can refer to external probes and survive demo-data resets.
GPS remains attached to source readings, not the probe or prediction.

Like the existing sensor endpoints, this endpoint currently has no authentication.
Add authentication before exposing ingestion to untrusted clients. Send requests
from the model backend; cross-origin browser ingestion is not configured.

## Close older predictions

Use **Close prediction** on a card to move it out of the default **Open
predictions** view. The change is saved in the database and survives refreshes.
Select **Closed predictions** to review older results and choose **Reopen
prediction** to bring one back. Closing never deletes the prediction.

Apply `npm run db:migrate` to add the `closed` column. Existing and newly
received predictions start open. The read API continues returning both open
and closed results and includes a `closed` boolean on each result.
